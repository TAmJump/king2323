GitHub Pages はデフォルトで Jekyll(静的サイトジェネレータ)を走らせる。本プロジェクトは Jekyll を使わない純粋な静的HTMLなので、空ファイル .nojekyll を置いて Jekyll を無効化している。

JST カウントダウンロジック(タイムゾーン非依存)

function nextFridayJST() {
  const now = new Date();
  // 現在時刻を UTC → JST(UTC+9)に変換
  const jstNow = new Date(now.getTime() + 9 * 3600 * 1000);
  // JST 上で次の金曜 23:23 を求める
  const day = jstNow.getUTCDay();   // 0=日 ... 5=金 ... 6=土
  const daysUntilFri = (5 - day + 7) % 7 || 7;
  const target = new Date(jstNow);
  target.setUTCDate(jstNow.getUTCDate() + daysUntilFri);
  target.setUTCHours(23, 23, 0, 0);
  // JST→UTCに戻す
  return new Date(target.getTime() - 9 * 3600 * 1000);
}

これにより、訪問者がどのタイムゾーンにいても東京時刻の金曜23:23を正確にカウントダウンする。

ChatGPT が生成した「.png」拡張子のファイルは中身が JPEG/RGB(透明度なし)。白背景部分を bone-white(#FAF7F0)に置換しただけでは、body のグラデーション overlay がある領域で実色がずれて「白い枠」が見えた。

8.3 v1.4 の解決法 — 真の PNG α透過

PIL での処理:

from PIL import Image
import numpy as np

src = Image.open(src_path).convert('RGB')
arr = np.array(src.convert('RGB')).astype(np.float32)

# min(R,G,B) で白さを測る
# min > 240 → α = 0(完全透明)
# min < 200 → α = 255(完全不透明)
# 中間で滑らかに補間(アンチエイリアス保持)
min_ch = arr.min(axis=2)
alpha = np.clip((240 - min_ch) / 40 * 255, 0, 255).astype(np.uint8)

rgba = np.dstack([arr.astype(np.uint8), alpha])
out = Image.fromarray(rgba, 'RGBA')
out.save('logo-v3.png', 'PNG')

function setGoogTransCookie(lang) {
  const host = window.location.hostname;
  const parts = host.split('.');
  const parentDomain = parts.length > 1
    ? '.' + parts.slice(-2).join('.')   // ".tamjump.com"
    : host;

  const value = lang === 'en' ? '' : `/auto/${lang}`;
  const expires = new Date();
  expires.setFullYear(expires.getFullYear() + 1);

  // 現在ドメインと親ドメイン両方にセット
  document.cookie = `googtrans=${value};path=/;expires=${expires.toUTCString()}`;
  document.cookie = `googtrans=${value};domain=${parentDomain};path=/;expires=${expires.toUTCString()}`;
}

function applyLang(lang) {
  setGoogTransCookie(lang);
  setTimeout(() => window.location.reload(), 100);
}

§16 運用上の罠リスト

本セッションで実際に踏んだ罠の記録。次セッションで同じ罠を踏むな。

罠 #1: PAT を「使えない」と判断する

新規Claudeが「セキュリティリスクがある」と git push を拒否しがち。本書 §3 に従い、PAT埋込clone は標準運用。御託は不要。

罠 #2: GitHub repo の初回push時にフォルダ構造が消える

User が Web UI で先にファイルをアップロードしていた場合、フォルダ構造がフラット化される(assets/logo-128.png が logo-128.png に)。force push でリポを上書きすれば直る。

git push -u origin main --force

罠 #3: GitHub Pages の Source 設定が「GitHub Actions」になっている

デフォルトでは Actions モード。これだと workflow が走らずビルドされない。必ず「Deploy from a branch」+ main / rootに変える。

罠 #4: ChatGPT 出力 .png が実際は JPEG

透明度がない。file コマンドで確認 → PIL で α threshold 処理。

罠 #5: display:none で Google翻訳が初期化拒否

#google_translate_element を display:none や left:-9999px にすると初期化失敗。画面内に opacity:0 で配置。

罠 #6: Google翻訳の .goog-te-combo が新UIで存在しない

InlineLayout.SIMPLE は select を作らない。Cookie方式に移行。

罠 #7: CSP で translate-pa.googleapis.com を忘れる

Google翻訳は3つのドメイン(translate.google.com / translate.googleapis.com / translate-pa.googleapis.com)を使う。全部CSPに追加すること。

罠 #8: script-src-elem 指令を書かないと一部ブラウザで失敗

Chrome は script-src にフォールバックするが、明示的に両方書く方が安全。

罠 #9: CSS .goog-te-gadget span { display:none } が select の親を隠す

Google翻訳UIを隠したいなら、banner-frame と tooltip だけに絞る。gadget 全体は触らない。

罠 #10: 翻訳されたくない箇所は translate="no" + class="notranslate" 両方

片方だけだとブラウザ・Google両方では効かないことがある。両方つける。

罠 #11: ブラウザキャッシュが頑固

同じファイル名のロゴを更新しても古いものが見える。新規ファイル名(logo-v3-*.png 等)で pushするか、URL に ?v={数字} を毎回違うもので付ける。

罠 #12: Cloudflare Proxy 経由で CSP が上書きされる

Cloudflare はデフォルトで CSP ヘッダーを返す場合がある。HTMLのmetaタグで明示的にCSPを定義すると上書きできる(メタ後勝ち)。

罠 #13: ロゴの「白い枠」問題

白背景のロゴをページ背景色に置換しただけでは、body のグラデーション overlay 領域で色がずれて枠が見える。真の PNG α透過でないと完全には消えない。

罠 #14: SVG filter の noise overlay が translate UI と干渉

body::before の noise が Google翻訳の隠し iframe と重なる場合がある。z-index:1000 に固定して翻訳UIより上にしておく。

罠 #15: Playwright スクリーンショットでフェードアニメ未完成

サンドボックスでローカル確認する際、fadeUp の opacity:0 で空に見えることがある。スクショ前に document.querySelectorAll('.fade-up').forEach(el => el.style.opacity = '1') で強制表示。

罠 #16: ユーザー指示「壊すな」と言われた箇所を守る

「これは壊すなよ」と言われたら、その後の修正で絶対に触らない。ヒーローの h1 + countdown + ロゴはこれに該当。

罠 #17: サンドボックスから tamjump.com へのアクセス不可

Claude のサンドボックスは allowlist 制で、tamjump.com は許可されていない。動作確認はユーザーのブラウザでスクショ依頼。
